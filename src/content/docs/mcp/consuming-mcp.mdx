Connecting an MCP server is easy. Deciding **what the model may use, and with which checks**, is the engineering. That decision always belongs to the **host**: your application.

## Option 1: a bridge into your own agent loop (Python)

Your Module 6 loop works with any MCP server through a small bridge: list the server's tools, convert them to Claude tool definitions (**keeping only an allow-list**), and route tool calls back to the server. Tested against the acme-ops server in-process:

```python
# app/agents/mcp_bridge.py: use any MCP server's tools from your own agent loop
import json

from mcp import Client


async def anthropic_tools(client: Client, allow: set[str]) -> list[dict]:
    """Convert MCP tool definitions into Claude tool definitions, keeping only allow-listed tools."""
    listed = await client.list_tools()
    return [
        {"name": t.name, "description": t.description or "", "input_schema": t.input_schema}
        for t in listed.tools
        if t.name in allow
    ]


async def run_mcp_tool(client: Client, tool_use_id: str, name: str, arguments: dict) -> dict:
    """Execute one tool call on the MCP server and shape the result as a Claude tool_result."""
    result = await client.call_tool(name, arguments)
    if result.structured_content is not None:
        content = json.dumps(result.structured_content)
    else:
        content = "\n".join(c.text for c in result.content if c.type == "text")
    block = {"type": "tool_result", "tool_use_id": tool_use_id, "content": content}
    if result.is_error:
        block["is_error"] = True
    return block
```

Real output:

```text
tools: [('get_shipment', ['shipment_id'])]
{'type': 'tool_result', 'tool_use_id': 'toolu_1', 'content': '{"shipment_id": "ACM-2025-000183", "status": "delayed", "location": "Antwerp", "eta": "2026-10-30"}'}
{'type': 'tool_result', 'tool_use_id': 'toolu_2', 'content': "Error executing tool get_shipment: No shipment 'nope'. Check the ID format ACM-YYYY-NNNNNN or ask the customer.", 'is_error': True}
```

Notice that the server's `ToolError` arrives as an `is_error` tool result, so the model can recover (ask the customer for the right ID), exactly like errors from your own tools in Module 6. For production, connect with `Client("https://mcp.acme.example/mcp")` plus the user's token (lesson 4).

## Option 2: the Claude API's MCP connector

For **remote** servers, the Claude API can connect to the MCP server itself, server-side, so you don't write the bridge. You declare the server and a toolset that references it (beta):

```python
import anthropic

client = anthropic.Anthropic()

response = client.beta.messages.create(
    model="claude-opus-5-5",
    max_tokens=16000,
    betas=["mcp-client-2025-11-20"],
    mcp_servers=[{
        "type": "url",
        "url": "https://mcp.acme.example/mcp",
        "name": "acme-ops",
        "authorization_token": user_access_token,  # the user's token, so the server enforces their permissions
    }],
    tools=[{
        "type": "mcp_toolset",
        "mcp_server_name": "acme-ops",
        "default_config": {"enabled": False},          # allow-list mode: everything off by default...
        "configs": {"get_shipment": {"enabled": True}},  # ...then enable only what Relay needs
    }],
    messages=[{"role": "user", "content": "Where is ACM-2025-000183?"}],
)
```

The trade-off: less code, but the calls happen between the API and the MCP server, so the server must be reachable from the internet, and your own per-call approval hooks don't run in between. Use your own bridge when you need approvals on each call, private network access, or full logging control.

## Option 3: the AI SDK's MCP client (TypeScript)

In a TypeScript product (Module 2), `@ai-sdk/mcp` connects to a server and turns its tools into AI SDK tools. This snippet type-checks against AI SDK 7, and includes a defence from lesson 6 (detecting changed tool definitions):

```ts
// app/api/chat/route.ts (excerpt): Relay's TypeScript agent using Acme's MCP server
import { anthropic } from '@ai-sdk/anthropic';
import { createMCPClient } from '@ai-sdk/mcp';
import { detectToolDrift, fingerprintTools, isStepCount, streamText, type ToolSet } from 'ai';

declare function loadApprovedFingerprints(): Promise<Awaited<ReturnType<typeof fingerprintTools>>>;

export async function answer(question: string, userToken: string) {
	const mcpClient = await createMCPClient({
		transport: {
			type: 'http',
			url: 'https://mcp.acme.example/mcp',
			headers: { Authorization: `Bearer ${userToken}` }, // the USER's token, so the server enforces their permissions
		},
	});

	const tools = await mcpClient.tools();
	const drift = detectToolDrift(await fingerprintTools(tools), await loadApprovedFingerprints());
	if (drift.changed.length || drift.added.length) {
		await mcpClient.close();
		throw new Error(`MCP tool definitions changed since review: ${[...drift.changed, ...drift.added].join(', ')}`);
	}

	return streamText({
		model: anthropic('claude-opus-5-5'),
		instructions: 'You are Relay, the support assistant for Acme Logistics.',
		prompt: question,
		tools: tools as ToolSet,
		stopWhen: isStepCount(5),
		onEnd: async () => {
			await mcpClient.close();
		},
	});
}
```

## Option 4: developer tools

Developers can use the same servers from their tools. For example, Claude Code connects to a remote server with:

```bash
claude mcp add --transport http acme-ops https://mcp.acme.example/mcp
```

A project can also commit an MCP configuration file so the whole team gets the same servers. Check your host's documentation for the exact configuration format, which differs between hosts.

## Host-side policy: what Relay actually allows

| Server | Tools allowed for Relay | Policy |
|---|---|---|
| acme-ops | `get_shipment`, `search_shipments` | Auto-approve (read-only) |
| acme-crm | `get_customer_overview`, `create_claim` | `create_claim` needs agent approval above 100 EUR |
| analytics (third-party) | none | Not connected for Relay at all |

Server **annotations** (`read_only_hint`, `destructive_hint`) are **hints from the server**, so useful but not trustworthy on their own. The host's own allow-list and approval policy decide. A malicious or buggy server can mark a destructive tool as read-only.

<ThinkFirst question="Relay's agent runs in Acme's private network and needs acme-ops (internal) plus a public weather MCP server. Which consumption option would you use for each, and why?">

- **acme-ops (internal): your own bridge (option 1).** The server isn't reachable from the internet (and shouldn't be), you want per-call approval hooks and full logging in Relay, and Relay passes each user's token so permissions are enforced per user.
- **Public weather server: either option works.** The Claude API's MCP connector (option 2) is simplest if the data isn't sensitive and you don't need per-call approvals. Your bridge is better if you want uniform logging and policies for every tool.

The general rule: **the more sensitive the data or the action, the more you want the calls to pass through your own host code**, where approvals, logging and budgets live.

</ThinkFirst>
