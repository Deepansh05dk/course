<Incident title="Right documents, wrong answer" severity="SEV2">
Relay retrieved exactly the right chunk for "Can customers return opened electronics?" (Policy 3.4: "Opened electronics can be returned within 14 days if all accessories are included"). It answered: "Yes, within 30 days." Retrieval was perfect. **Generation** mixed the retrieved text with the general 30-day refund rule it had seen elsewhere in the context, and nobody checked the answer against the source.
</Incident>

Retrieval gets the evidence into the room; **generation** must stick to it. This lesson covers the last mile: instructions, citations, refusals, and conflicting sources.

## The grounding prompt

```python
SYSTEM = """You are Relay, the support assistant for Acme Logistics.

Answer ONLY from the policy documents provided in this conversation.
- If the documents do not contain the answer, say: "The policy documents don't cover this." and suggest escalating to the policy team.
- If documents conflict, prefer the one with the latest effective date, and mention the conflict.
- Quote exact numbers, deadlines and conditions as written. Don't round or generalise them.
- Never use general knowledge about refunds, shipping or customs. Acme's documents are the only source."""
```

That's necessary, but not sufficient: prompts reduce ungrounded answers; they don't eliminate them. You also need citations you can verify, and evals that measure **faithfulness** (Module 5).

## Native citations: provable pointers into your sources

Rather than asking the model to write `[S1]` markers (which it can invent), several APIs offer **native citations**. With Claude, you pass each retrieved chunk as a `document` block with citations enabled. The response comes back as text blocks, and cited claims carry pointers to the exact passage, which the API guarantees are valid locations in the documents you provided:

```python
import anthropic

client = anthropic.Anthropic()


def answer_with_citations(question: str, chunks: list[dict]) -> dict:
    documents = [
        {
            "type": "document",
            "source": {"type": "text", "media_type": "text/plain", "data": c["content"]},
            "title": f'{c["doc_title"]}, {c["section"]}',
            "context": f'Effective date: {c["effective_date"]}',
            "citations": {"enabled": True},
        }
        for c in chunks
    ]
    response = client.messages.create(
        model="claude-opus-5-5",
        max_tokens=4000,
        system=SYSTEM,
        messages=[{"role": "user", "content": [*documents, {"type": "text", "text": question}]}],
    )
    parts, sources = [], []
    for block in response.content:
        if block.type != "text":
            continue
        parts.append(block.text)
        for cite in block.citations or []:
            sources.append({
                "chunk_id": chunks[cite.document_index]["id"],  # map back to your chunk
                "quote": cite.cited_text,                        # the exact supporting passage
            })
    return {"answer": "".join(parts), "sources": sources}
```

Each `char_location` citation includes the `document_index`, the `cited_text`, and character offsets, which is everything your UI needs to render the citation chips with highlighted excerpts from Module 2. Two notes from the API docs: `cited_text` doesn't count toward output tokens, and citations **can't be combined with structured outputs** in the same request. If you need both, generate the cited answer first and extract structured fields in a second step.

:::note[Valid pointer ≠ supported claim]
The API guarantees the citation points at real text in your documents. It doesn't guarantee that the passage *supports* the sentence it's attached to. Checking support is a faithfulness eval (Module 5): code checks for numbers and dates, plus an LLM judge.
:::

Calibrate the threshold on your eval set: include unanswerable questions, and tune the threshold so that most of them refuse while few answerable ones do.

## Conflicting and outdated sources

Real corpora contradict themselves: a 2023 policy and its 2026 replacement, a regional exception, a draft that was never deleted. Make conflicts **resolvable**:

- Store `effective_date`, `version` and `status` (draft or active) as metadata (ingestion lesson), and pass them to the model (the `context` field above).
- Filter out drafts and superseded versions at **retrieval time** when you can. Don't rely on the model to ignore them.
- When two active sources disagree, show both to the user rather than silently picking one.

<ThinkFirst question="An Acme agent asks: 'Can an insured shipment of glassware to Norway get full declared-value compensation?' Relevant chunks: the damage policy table (fragile items capped at 100 EUR), the insurance policy (insured = declared value), and a Norway customs note. What should a well-grounded answer look like, and what should the system do with it?">

**A good answer surfaces the conflict instead of picking one rule:**

> "The policies conflict for this case. Insured shipments are compensated up to the declared value [Insurance policy §2], but fragile items (glass, ceramics) are capped at 100 EUR [Damage policy §2, table]. The documents don't say which rule takes precedence for insured fragile items. Escalate to the claims team before promising an amount."

**What the system should do:**

1. Render each citation as a chip with the highlighted excerpt.
2. Detect the conflict signal ("conflict", or two sources with different numeric limits on the same topic) and show a "sources disagree" banner with an escalation button (Module 2).
3. Log the case. It's a **policy gap**, and a valuable output of the AI system: the policy team should resolve it, and the resolution becomes an eval case.

</ThinkFirst>
