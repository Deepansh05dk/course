## The three metrics

For two vectors **a** and **b**:

| Metric | Formula (intuition) | Range | "Closer" means | Sensitive to length? |
|---|---|---|---|---|
| **Dot product** | Σ aᵢ·bᵢ | −∞ to +∞ | **Larger** | Yes: long vectors score higher |
| **Cosine similarity** | dot(a, b) ÷ (‖a‖·‖b‖) | −1 to 1 | **Larger** | No: only the angle matters |
| **Euclidean (L2) distance** | √Σ(aᵢ − bᵢ)² | 0 to +∞ | **Smaller** | Yes |

Vector databases often express everything as a **distance** (smaller is closer), so cosine *similarity* becomes cosine *distance* = 1 − similarity. Watch the sign conventions: pgvector's `<#>` operator returns the **negative** inner product so that "smaller is closer" holds for every operator.

## The normalization trick

If every vector is normalized to length 1:

- **Cosine similarity = dot product** (the denominators are 1).
- **L2 distance** depends only on the angle: ‖a − b‖² = 2 − 2·cos(a, b). So ranking by L2 gives the same order as ranking by cosine.

That's why a common production pattern is: **normalize once at write time, then use the fastest operation (dot product) at query time.** All three metrics then agree on ranking.

```python
import numpy as np

a = np.array([3.0, 4.0])
b = np.array([6.0, 8.0])          # same direction, twice as long

cos = a @ b / (np.linalg.norm(a) * np.linalg.norm(b))
print(cos)                        # 1.0  -> identical direction
print(a @ b)                      # 50.0 -> grows with length
print(np.linalg.norm(a - b))      # 5.0  -> "far apart" by L2

def unit(v): return v / np.linalg.norm(v)
ua, ub = unit(a), unit(b)
print(ua @ ub, np.linalg.norm(ua - ub))   # 1.0, 0.0 -> after normalization, all agree
```

## Which one should you use?

**Use the metric the embedding model was trained for.** The model's documentation says so. Most text-embedding models are trained with cosine similarity, and many already return normalized vectors.

- **Cosine (or dot product on normalized vectors):** the default for text embeddings. Length usually carries no useful meaning.
- **Dot product on unnormalized vectors:** some models (and recommender systems) deliberately encode "importance" or "popularity" in vector length. Normalizing would throw that away.
- **L2:** common for image and some other embeddings; equivalent to cosine for normalized vectors.

<ThinkFirst question="A recommender team stores product embeddings where vector length encodes popularity (popular products have longer vectors). Product wants 'similar items' on product pages. Which metric would you use, and would your answer change for a 'trending items' feature?">

**"Similar items": cosine similarity.** Similarity of *kind* is about direction. Using dot product would push popular products into every list, even when they're only loosely related (the "long documents always win" problem, deliberately).

**"Trending" or "recommended for you": dot product can be the right choice**, precisely because it rewards both relevance (direction) and popularity (length). That's a feature, not a bug.

The general lesson: **the metric encodes a product decision.** Know what length means in your vectors before choosing.
